### 프로젝트 상태

- **배포:** 고급유노트(Octane95)는 이미 Google Play 스토어에 정식 공개된 앱.
- **제품 원칙:** 옥탄가에 민감한 운전자를 위한 오프라인 우선 계산·주유 기록 앱. 기록의 번거로움은 줄이되 선택 데이터의 정확도는 유지.
- **사용 현황(공유받은 자료 기준):** 설치 기반 약 12\~13대. 최근 30일 Firebase 활성 사용자 6명, 총 이벤트 124회, 기록 조회 14회/5명, 계산기 진입 11회/3명, 계산 완료 6회/2명. 기간·지표 정의가 달라 설치 유지율이나 유입 경로를 확정할 수 없음. 블로그 소개 글 게시 이력은 있으나 유입 경로 미확인.
- **개발 테스트:** 네트워크에 연결하지 않는 별도 공기기에서 오프라인 테스트 중.
- **브랜드:** 기존 주유기 95 레드 로고와 일관성 있는 라이트 배경·딥네이비 텍스트·레드 포인트 테마 적용.

### 최근 구현 내용 — 개발자 보고 및 실기기 화면 기준

1. **계산:** 단순 혼합, 탱크 기준(단일/혼합 주유), 목표 맞추기 3모드 및 계산 결과·조건 요약.
2. **주유 기록:** 계산 결과만 빠르게 저장하거나 상세 주유 정보를 입력하여 저장. 주유소, ODO, 가득 주유, 금액, 메모 지원.
3. **실제 주유량 분리:** `OctaneLog.actualRefuelLiter: double?`을 Hive 필드 8로 추가. 계산상 주유량과 실제 주유량을 구별하며, 목표 맞추기에서 산출한 필요량은 자동 확정하지 않음.
4. **기록 기준 Full-to-Full 실연비:** 시작 가득 주유 주유량 제외, 그 이후 부분 주유들과 종료 가득 주유 주유량 합산. 누락·역행 ODO, 유효하지 않거나 누락된 실제 주유량이 있으면 구간 결과 제외. 기존 계산 입력값을 확정 실연비로 사용하지 않음. 통계 화면에 실연비 영역 반영.
5. **백업:** Hive 과거 기록의 신규 필드 null 호환 및 JSON 백업/복원 선택 필드 설계. 앱 메뉴에 백업 파일 저장·공유·불러오기 기능 표시.
6. **전면 UI 개편(Claude Code 작업 보고):** `lib/theme/app_theme.dart`, `lib/widgets/app_widgets.dart` 추가; `lib/main.dart`, `lib/history_detail_page.dart` 개편. 홈, 계산/결과, 저장 BottomSheet, 기록 목록, 통계, 차량, 더보기, 기록 상세/수정 전반을 통일.
7. **기록 기능 개선:** 혼합 주유 기록 수정 지원, 중복 목표 맞추기 카드 정리, 금액 계산용 주유량 입력 제거, 기록 대상 기반 삭제, 통계 시간순 정렬, 차트 툴팁 대비 수정. 모두 개발자 작업 보고 기준이며 기능별 자동 테스트 최종 통과는 별도 확인 필요.

### 실제 화면 검토에서 확인한 사항

- 홈: 계산 바로가기, 최근 주유 기록, 월간 요약. 차량 등록 없이 계산 가능.
- 기록 목록: 계산 모드 필터, 시간순 기록, ODO/가득 주유 정보의 조건부 표시.
- 계산/결과: 계산 입력을 그룹화하고 결과의 최종 RON을 강조. 빠른 저장과 상세 저장의 목적은 더 명확하게 표현할 여지 있음.
- 저장 BottomSheet: 실제 주유량, 가득 주유, ODO, 추가 정보. 화면 하단에서 저장 버튼과 시스템 내비게이션 영역이 겹쳐 보이는 캡처가 있어 실기기 확인 및 수정 필요.
- 통계: 옥탄가 통계·추이와 기록 기준 실연비를 표시. 유효한 Full-to-Full 구간이 없으면 부족한 기록 조건을 안내.
- 차량/더보기: 차량 미등록 안내와 주유비·월간 리포트·백업·도움말 등의 메뉴가 표시됨. 준비 중인 기능을 구현 완료로 간주하지 않음.

# **Octane95 **

## **프로젝트 개요**

**Octane95**는 차량 주유 시 고급유와 일반유를 혼합했을 때의 평균 옥탄가를 계산하고, 차량별 권장 옥탄가 기준에 맞춰 현재 연료 상태를 확인할 수 있는 Flutter 기반 모바일 앱이다.

사용자는 주유량, 기존 연료 정보, 추가 주유 정보를 입력해 현재 탱크의 예상 옥탄가를 계산할 수 있으며, 계산 결과를 기록으로 저장해 나중에 다시 확인할 수 있다.

## **프로젝트 목적**

일반유와 고급유를 혼합해서 사용하는 운전자가 매번 직접 계산하지 않아도 평균 옥탄가를 쉽게 확인할 수 있도록 돕는 것이 목적이다.

특히 권장 옥탄가가 높은 차량을 운용하는 경우, 현재 연료 상태가 차량 기준에 적합한지 빠르게 판단할 수 있도록 한다.

## **핵심 기능**

| **기능** | **설명** |
| --- | --- |
| 평균 옥탄가 계산 | 고급유와 일반유 주유량을 입력해 평균 옥탄가를 계산 |
| 혼합 옥탄가 계산 | 기존 연료와 추가 주유 연료를 기준으로 최종 옥탄가 계산 |
| 차량 프로필 저장 | 차량명, 연식, 권장 옥탄가, 경고 기준, 탱크 용량 저장 |
| 상태 판정 | 계산된 옥탄가가 차량 기준에 적합한지 표시 |
| 계산 기록 저장 | 계산 결과와 입력값을 로컬에 저장 |
| 기록 상세 보기 | 저장된 계산 기록의 입력값과 결과 확인 |
| 기록 삭제 | 불필요한 기록을 삭제 가능 |
| 통계/차트 | 저장된 기록을 기반으로 평균, 최고, 최저 값 확인 |

## **현재 진행 상황**

현재까지 계산, 기록 저장, 기록 상세 보기, 차량 프로필 저장 기능이 구현되어 있다.

최근에는 차량 탭의 임시 화면을 제거하고 실제 차량 프로필 입력 및 저장 화면으로 교체했다. 저장된 차량 정보는 계산 결과 상태 판정에 활용되며, 사용자는 차량 정보 삭제도 가능하다.

또한 기록 화면에서는 계산 히스토리, 통계 카드, 차트, 상세 페이지 이동, 롱프레스 삭제 기능이 연결되어 있다.

## **프로젝트 방향성**

Octane95는 단순 계산기에서 출발했지만, 차량별 연료 관리 도구로 확장할 수 있는 가능성이 있다.

단기적으로는 계산 정확도, 기록 관리, 차량 프로필 기능을 안정화하는 것이 중요하다. 이후에는 차량별 히스토리, 목표 옥탄가 계산, 주유 비용 기록, 연비 기록 등으로 확장할 수 있다.

최종적으로는 “고급유/일반유 혼합 주유를 관리하는 개인용 연료 노트”에 가까운 앱으로 발전시키는 것이 목표다.

## **2026-10 업데이트 및 성장 방향**

### **최근 기능 업데이트**

- 옥탄가 계산 UI를 `단순 혼합 / 탱크 기준 / 목표 맞추기` 3개 모드로 재정리
- 탱크 기준 계산에서 `단일 연료 / 혼합 주유` 입력 방식 지원
- 목표 옥탄가 역산 계산 기능 고도화
- 계산 결과와 기록 저장 단계를 분리해 UX 단순화
- 기록 저장 BottomSheet 도입
- 주유 기록에 주유소, 현재 주행거리(ODO), 가득 주유 여부 추가
- 금액 정보는 선택 입력으로 유지
- 기록 상세 화면에서 미입력 값 표현과 정보 구조 개선
- 백업/복원 기능은 기존 데이터 호환성을 유지하면서 내장 저장소 저장 방식 검토
- 전체 테마는 기존 다크 네이비 기반에서 브랜드 로고와의 일관성을 고려해 소프트 다크/레드 포인트 계열도 검토 중

### **현재 제품 방향**

고급유노트는 단순 옥탄가 계산기보다 `내 차의 연료 상태와 주유 이력을 관리하는 앱` 방향으로 확장한다.

핵심 흐름:

1. 계산
2. 기록 저장
3. 주행거리/가득주유 데이터 축적
4. 실연비 및 연료비 분석
5. 월간 리포트
6. 공유 가능한 결과 카드

계산 기능 자체를 늘리는 것보다, 기록이 쌓일수록 사용자에게 더 많은 가치를 주는 구조를 우선한다.

### **Analytics 현황 및 개선 방향**

현재 Firebase Analytics에서 확인되는 주요 이벤트:

- open\_records
- user\_engagement
- calculate\_completed
- app\_open
- open\_vehicle
- open\_calculator
- calculate\_tank

현재는 이벤트 횟수 중심이라 계산 이후 기록 저장까지 이어지는 전환을 정확히 보기 어렵다.

추가/정비 예정 이벤트:

- calculate\_simple
- calculate\_tank\_single
- calculate\_tank\_mixed
- calculate\_target
- calculate\_completed
- calculate\_failed
- record\_save\_started
- record\_saved
- record\_save\_cancelled
- record\_edited
- record\_deleted
- open\_record\_detail
- backup\_exported
- backup\_restored

주요 분석 목표:

- 계산 완료 → 기록 저장 전환율
- 기록 저장 시 ODO 입력률
- 가득 주유 체크 사용률
- 혼합 주유 기능 사용률
- 목표 맞추기 사용률
- 백업 기능 사용률

실제 주유소명, ODO 값, 금액, 메모 등 사용자 원본 데이터는 Analytics에 전송하지 않고 boolean/category 위주로 수집한다.

### **다음 개발 우선순위**

| **우선순위** | **작업** | **목적** |
| --- | --- | --- |
| 1 | Firebase Analytics 이벤트 체계 정리 | 계산 → 저장 → 재방문 흐름 측정 |
| 2 | Full-to-Full 실연비 | ODO + 가득 주유 데이터를 실제 사용자 가치로 전환 |
| 3 | 월간 연료 리포트 | 주행거리, 총 주유량, 주유비, 평균 옥탄가, 실연비 요약 |
| 4 | 일반유 대비 프리미엄 비용 분석 | 고급유 사용에 따른 추가 비용 시각화 |
| 5 | 계산 결과/월간 리포트 공유 카드 | 자연스러운 외부 확산 루프 구축 |

### **확산 전략**

광고 집행보다 먼저 반복 사용 구조를 만든다.

주요 타깃:

- 고급유 권장 차량 운전자
- 터보 차량 사용자
- 일반유와 고급유를 혼합 주유하는 사용자
- 옥탄가와 주유비를 직접 관리하는 사용자

콘텐츠 유입 예시:

- 고급유 20L + 일반유 10L이면 몇 RON인가?
- 잔유가 있을 때 최종 옥탄가는 어떻게 계산하는가?
- 목표 RON 95를 맞추려면 고급유가 몇 L 필요한가?
- 고급유 사용 시 실제 연비와 비용 변화는 어떤가?

확산 루프:

`검색/커뮤니티/콘텐츠 → 계산 → 기록 → 리포트 → 공유 → 신규 유입`

초기에는 설치 수 자체보다 반복 사용 사용자와 기록 저장 비율을 핵심 지표로 본다.

### **제품 장기 방향**

장기적으로 홈 화면은 단순 계산기 진입점보다 차량 연료 상태 대시보드에 가깝게 발전시킨다.

예상 정보:

- 최근 계산 옥탄가
- 마지막 주유일
- 현재 ODO
- 최근 실연비
- 이번 달 주유 횟수/주유량/주유비
- 평균 옥탄가
- 최근 기록 바로가기

최종 목표는 `계산기`가 아니라 `개인 차량 연료 관리 노트`로 자리잡는 것이다.
